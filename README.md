# batWingSensoryHairs
Supplementary code for the study “Modeling the functional capabilities of the bat wing hair sensor network: effective sensor distributions from optimal sensing” by Eckstein et al, 2026.
This repository contains all scientific code used for the complex wing case presented in the paper. <br> <br>
**Results Data Files** <br> <br>
Due to GitHub file size limitations, existing results files are not hosted in this repository. Find existing results data files at https://huggingface.co/datasets/NIEckstein/batWingSensoryHairs <br>
Download that repository and this repository to the same folder to run any code from this repository using our existing results files. <br> <br>
**Results generating codes:** <br> <br>
**“root_buildAWing.m”** sets up a wing model and generates perturbations of the empirical kinematic data found in the folder, “batData”. This script sets all geometric parameters, but it does not set material/aerodynamic properties.  <br> 
**“root_simulateBatWing.m”** reads a setup file produced by “root_buildAWing.m” and does the simulation, simulating each perturbed trajectory in parallel on separate CPU cores. Material and aerodynamic properties are set in the beginning of the script before simulation.   <br> 
**“root_optimizePrecisions_strainMagnitudeFormulation.m”** reads a simulation results file produced by “root_simulateBatWing.m” and does the optimization calculation for the strain magnitude formulation. It uses the paired measurements of aerodynamic force and strain from the simulation to construct covariance matrices, which it then uses for the optimization calculation. This script sets the constraint on decoder mean squared error of the aerodynamic force estimate by first finding the maximum decodable aerodynamic force variance, assuming no strain sensor noise, and it then multiplies this by a factor less than 1 to get a minimum decodable variance bound (this factor appears in the existing optimization results file names following the tag “3DrsqrFrac” to indicate what the constraint was for that optimization). From this lower bound on decodable variance, the maximum MSE bound is computed and passed to the optimization constraint function. The optimization cost and constraint functions are defined at the bottom of the script.   <br> 
**“root_optimizePrecisions_uniaxialStrainFormulation.m”** reads a simulation results file produced by “root_simulateBatWing.m” and does the optimization calculation for the uniaxial strain formulation. Everything works the same as in “root_optimizePrecisions_strainMagnitudeFormulation.m” except for the strain sensor formulation.  <br> <br>
**Analysis and visualization codes:**  <br>   <br> 
**“root_plotBatWingsWithOptimalPrecisions_strainMagnitudeFormulation.m”** and **“root_plotBatWingsWithOptimalPrecisions_uniaxialStrainFormulation.m”** read output files from the corresponding optimization codes to generate plots showing the optimal precisions. They are setup to plot multiple sets of optimal precisions in a loop. <br>
**“root_animateSimWing.m”** generates an animation of a simulated wing from a simulation results file. It is setup to only animate one simulated trajectory for each run of the script.  <br> 
**“root_animatePerturbedSkeletons.m”** generates an animation of just the skeletal wing frame from a simulation results file, with the original and kinematically perturbed skeletons overlaid in the same animation to visualize the trajectory variability introduced by our perturbation scheme.  <br> 
**“root_compareOptimalPrecisions.m”** compares different sets of optimal precisions to one another to test for positive spatial correlation. It uses Lee’s L statistic to quantify correlations between precision distributions, and it computes a one-sided significance test for each comparison using empirical distributions derived from random permutations of the sensor locations. It can handle comparisons between results based on the same strain sensor formulation, but it is not set up to compare across strain formulations.  <br> 
**“root_compareOptimalPrecisionsAcrossFormulations.m”** same as above, but it is set up such that you must do at least one comparison across strain formulations  <br> 
**“root_empiricalConstraintConvexityCheck.m”** checks thousands of pairs of arguments to the optimization constraint function to look for examples that violate the convexity inequality condition: f((xi+xj)/2)≤(f(xi)+f(xj))/2. It has never found any for us. Taken together with the fact that the L1 norm cost is convex, this indicates the optimization problem as a whole is convex. <br> <br>
